# Hermes Desktop v0.7.8

Hermes Desktop v0.7.8 catches up with Hermes Agent v0.23.1 and retains support for older Agent installations.

## Agent compatibility

Interactive tool requests now work with the current Agent request protocol across Local, SSH and direct Remote transports.

- Approve or deny commands using the exact request that asked for permission.
- Answer multi-question clarification forms in one submission, including multiple-choice selections.
- Restore unanswered questions after reconnect and disable controls when the Agent cancels a request.
- Enter passwords and secrets through a native prompt; values stay out of chat history.
- See a Desktop update recommendation when a connected Agent uses a newer protocol than this release supports.
- Connect to fresh Remote and SSH backends before session history exists.
- Keep current clarification requests interactive when chat adopts a replacement runtime.
- Restore tool activity from current Agent history responses as well as older installations.

## Installation and updates

Fresh installations use a reviewed Agent v0.23.1 baseline, and runtime discovery follows the Agent-managed launcher instead of assuming an old virtual-environment layout.

- Verify pinned POSIX and Windows installer bytes before execution.
- Refresh runtime paths after install or update without restarting Desktop.
- Prefer current managed Agent launchers on SSH hosts, including custom home paths containing spaces.
- Retain legacy Agent installation support and profile-scoped command routing.
- Use the headless backend for managed local installations.
- Preserve the Agent-selected Windows interpreter so raw helper output remains available, while background commands stay hidden.
- Publish the Linux arm64 updater feed alongside the AppImage so installed arm64 clients can discover stable updates.
- Package only compiled application files, runtime assets, license and production dependencies, excluding repository tooling and local development settings.

## Upgrade notes

Desktop and Agent remain independently updated products; remote hosts retain ownership of their Agent installation.

Older Agents continue using their existing event protocol. Updating Desktop does not silently replace a Remote Agent or downgrade a newer local install. A Windows managed install with only a `hermes.cmd` launcher needs Agent repair to restore its native `hermes.exe` launcher.
